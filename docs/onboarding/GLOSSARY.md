# Project Glossary

Welcome! This glossary explains common terms, acronyms, and project-specific language you'll encounter. If you see a term you don't know, check here—or add it if it's missing!

| Term                | Definition                                                                                  |
|---------------------|---------------------------------------------------------------------------------------------|
| **Makefile**        | A file containing build and automation commands, run with `make`. Used for setup, tests, etc. |
| **Docker**          | A tool for running software in isolated containers. Used here for consistent dev environments. |
| **Rule Proposal**   | A suggestion for a new or updated rule in the system, submitted via the API or UI.           |
| **API**             | Application Programming Interface. The backend server you interact with (FastAPI in this project). |
| **Container**       | An isolated environment for running software, managed by Docker.                             |
| **Test Suite**      | A collection of automated tests to check if the code works as expected.                      |
| **Pytest**          | The testing framework used for Python code in this project.                                  |
| **Admin Token**     | A special authentication token with admin privileges, needed for certain API actions.        |
| **Frontend**        | The user interface (UI) part of the project, built with React.                              |
| **Backend**         | The server/API part of the project, built with FastAPI.                                     |
| **Environment Variable** | A setting that configures how software runs (e.g., ports, database URLs).               |
| **CI/CD**           | Continuous Integration/Continuous Deployment. Automated systems for testing and deploying code. |
| **Fixture**         | In testing, a reusable setup (like a mock database or user) provided to tests automatically. |
| **Endpoint**        | A specific URL path in the API that performs an action or returns data.                     |
| **UUID**            | Universally Unique Identifier. Used for unique IDs in the database.                         |
| **Changelog**       | A record of changes, updates, and fixes in the project.                                     |
| **Coverage Report** | A summary showing which lines of code are tested by the test suite.                         |
| **Onboarding**      | The process and documentation for getting new users or developers up to speed.              |
